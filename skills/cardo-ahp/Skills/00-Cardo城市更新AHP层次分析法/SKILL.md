# 00 · Cardo城市更新AHP层次分析法（总控 / 唯一入口）

本技能不实现算法，只负责**编排**：按顺序调用 `Skills/01..09`，每步跑完过闸门，不通过就停并说明原因。
所有产物落在工作区（默认 `CardoAHP/`）的 `过程文件/<编号-名称>/`；成果只输出 Office 文件。

## 文件边界（硬约定）

| 目录 | 允许 | 不允许 |
|---|---|---|
| `输入文件/` | xlsx / docx / pdf（模板、问卷、专家名单、方案评分表、来源说明） | JSON、MD 等 |
| `成果文件/` | `AHP权重表.xlsx`、`AHP方案评分结论.xlsx`、`AHP权重与评分结论.docx` | JSON、MD 等 |
| `过程文件/` | 任意（JSON 机读产物、md 报告、诊断记录、运行日志都在这） | — |

第 09 步有**边界闸门**：扫描输入/成果，出现非常规扩展名即失败并列出文件。JSON 只作为过程产物存在。

## 何时使用

- 要「完整跑一遍 AHP」→ `run`（默认 01→09）。
- 只换了方案评分 → 改 `输入文件/03-方案打分表/AHP方案评分表.xlsx`，然后 `run --from 08`。
- 想看跑到哪了、哪些产物在 → `status`。
- 想另开一个文件夹用别的评分做对照测试 → `scaffold`（技能链整体复制，互不影响）。

## 调用方式（两种，等价）

**A. Agent 逐步调用（首次/调优时用）**
按 [01](../01-指标体系/SKILL.md) → [02](../02-问卷生成/SKILL.md) → [03](../03-回收校验/SKILL.md) →
[04](../04-多专家聚合/SKILL.md) → [05](../05-权重与一致性/SKILL.md) → [06](../06-一致性校准/SKILL.md) →
[07](../07-权重表导出/SKILL.md) → [08](../08-方案打分/SKILL.md) → [09](../09-成果验证与成稿/SKILL.md)
逐个读 SKILL.md 并执行其中命令，每步确认闸门再进下一步。

**B. 总控脚本一键执行**

```powershell
# 在工作区根目录执行（如 <项目文件夹>\CardoAHP）
python Skills/00-Cardo城市更新AHP层次分析法/scripts/pipeline.py status --workspace .
python Skills/00-Cardo城市更新AHP层次分析法/scripts/pipeline.py run    --workspace .
python Skills/00-Cardo城市更新AHP层次分析法/scripts/pipeline.py run    --workspace . --from 08
```

退出码：0 全过；1 某步失败（含闸门未过或脚本报错，报告有原因）；2 参数/工作区/前置产物问题。
新工作区首次必须跑全链（`--from 08` 会因缺 05 步权重产物被前置检查拦下）。

## 开新文件夹换评分测试

```powershell
# 1) 生成独立测试工作区（复制 00+01..09 全链、模板、问卷、专家名单、评分表）
python Skills/00-Cardo城市更新AHP层次分析法/scripts/pipeline.py scaffold `
  --target "<项目文件夹>\AHP测试-A" --project-name "AHP评分对照-A" --baseline none

# 2) 编辑新工作区的 输入文件/03-方案打分表/AHP方案评分表.xlsx
#    黄色格填 0-10 分；「依据-方案X」列写出处；「方案信息」表登记方案编号/名称
# 3) 首次跑全链；之后每换一次评分只跑评分段
python .../pipeline.py run --workspace "<项目文件夹>\AHP测试-A"
python .../pipeline.py run --workspace "<项目文件夹>\AHP测试-A" --from 08
```

`--baseline` 三档：`none`（默认，只做结构自洽验证，换评分用）｜`weights`（问卷不变、校验权重与模板 sha）｜`full`（连得分基线一起回归）。

## 步骤与闸门

| 步 | 技能 | 主要产物 | 关键闸门 |
|---|---|---|---|
| 01 | 指标体系 | 过程：指标目录.json/.md | 准则+指标非空、criterionId 对得上、每指标有锚点 |
| 02 | 问卷生成 | 过程：空白问卷；输入：专家名单.xlsx | 份数=专家数（5-7）、专家名单为 xlsx |
| 03 | 回收校验 | 过程：回收校验报告 | 结构问题=0、CR 警告=0、份数≥5、总体 pass |
| 04 | 多专家聚合 | 过程：群体矩阵.json | 几何平均口径、专家≥5、聚合一致性 pass |
| 05 | 权重与一致性 | 过程：矩阵集/权重表/一致性 | 权重和=1、CR<0.1 全过 |
| 06 | 一致性校准 | 过程：诊断-*.json、校准记录.md | 无 CR≥0.1（有则人工批准后回 05） |
| 07 | 权重表导出 | 成果：AHP权重表.xlsx；过程：权重表.json | 回读对账 ok、模板 sha 前后不变 |
| 08 | 方案打分 | 过程：打分.json、评分表.json；成果：AHP方案评分结论.xlsx | xlsx→JSON 成功、方案数一致、全部出分 0-10、排序连续 |
| 09 | 成果验证与成稿 | 过程：独立验证结果.json、结论稿.md；成果：AHP权重与评分结论.docx | 独立复算 0 失败、**输入/成果仅含 Office** |

第 09 步基线来自 `记忆与规则/验证基线-CardoAHP.json`（可删）。有基线时额外校验权重、得分、排序、模板 sha；
无基线只做结构验证，报告标「跳过」，不算失败。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--workspace` | 技能所在工作区 | 工作区根，含 `Skills/ 输入文件/ 过程文件/ 成果文件/` |
| `--from` / `--to` | 01 / 09 | 只跑区间；`--from 08` 常用（只换评分），前置缺失会被明确拦下 |
| `--experts` | 工作区参数.json 或 5 | 空白问卷份数（规则区间 5-7） |
| `--project-name` | 某某片区改造项目 | 写入问卷、评分表表头与结论 docx |

## 产物与日志

- 过程：`过程文件/01..09-*/`（JSON、md、诊断、校验报告全在此）
- 总控：`过程文件/00-总控/运行日志.json`（每条命令、退出码、输出文件）+ `运行报告.md`（闸门表）
- 成果：`AHP权重表.xlsx`、`AHP方案评分结论.xlsx`、`AHP权重与评分结论.docx`

## 常见问题

- **第 08 步报「评分表存在下列问题」**：按提示行号改 xlsx（越界/非数字/指标ID 被改坏），改完 `--from 08`。
- **第 08 步报缺少评分表**：已自动生成空白模板，填好再跑。
- **`--from 08` 报缺少前置产物**：新工作区还没跑过 01→07，先跑全链（或 `--from 01 --to 07`）。
- **第 03 步失败**：问卷被改坏/缺格 → 让专家重填，禁止在聚合前替专家改数。
- **第 06 步失败（CR≥0.1）**：按 `校准记录.md` 用 `ahp_calibrate.py apply --approve-by` 人工批准，再 `--from 05`。
- **第 09 步边界闸门失败**：把误放进 输入/成果 的 JSON/MD 移到 `过程文件/`。
