> 第 4 件《AHP依据对照表.xlsx》：按「成稿章节 → 数值 → 源文件#键」逐项回指，
> 每个数都能追到 `权重表.json` / `评分表.json` 的具体字段；同时拦截依据格里的
> 占位措辞（`BAD_WORDS`）和正文段落里的标签错配（如把贡献值标成「权重」）。
> `--demo` 只加页脚标识，不放宽任何校验。

> `--aggregation` 提供专家人数等实际值，避免成稿把「5 位专家」写死成样例数。

独立验证退出码：0 无失败项（允许「跳过」）；1 有失败项；2 输入错。

## 两类验证

**A. 结构自洽（永远执行，无需基线）**
1. 矩阵齐全且与权重表准则一一对应；2. 准则权重和=1；3. 各准则局部权重和=1；4. 综合权重和=1；
5. 全部矩阵 CR<0.1；6. 双算法差 Δ ≤ max(1e-12, CR)；7. 引擎权重=独立复算；8. 引擎评分=独立加权；
9. 排序自洽（独立复算=引擎 ranking）；10. 评分完整性（每方案出分且在 0-10）。

> 第 6 项判据说明（2026-10-30 修正）：原先写死 `Δ≤1e-12`，等价于要求「矩阵完全一致」。
> 几何平均法与特征值法对**不一致**矩阵给出不同近似解，差值与不一致度同阶
> （实测 Δ/CR 稳定在 0.06~0.16），真实专家判断必然有分歧（CR>0）→
> 旧判据会让 09 步对任何真实项目都必 FAIL。改为相对判据 `Δ ≤ max(1e-12, CR)`；
> CR=0（完全一致矩阵）时仍要求精确相等。

**B. 基线对账（基线文件存在且含字段时才做）**
准则权重、综合权重、方案得分、排序、模板 sha256。缺字段/指标集不一致记「跳过」，不算失败。

**C. 成稿数值回指（`依据对照表.py`）**
- 表格里的数要能在对照表里找到对应行（章节 + 对象 + 数值 + `源文件#键`）；
- **正文段落里的数**若紧邻「权重 / 得分 / 贡献 / 占比 / 得分率」等标签，必须与对应 JSON 字段对得上——
  防止「数有出处、标签被换」（例：贡献值 0.744001 被写成「权重」，实际权重 0.095385）；
- 依据格出现 `合成演示 / 非真实依据 / 示例数据 / 演示数据` 任一词即判不通过（`BAD_WORDS` 不放宽）。
- **派生值必须有登记行**：拉分项贡献写 `派生：评分表.json#…score × 权重表.json#indicators[i].globalWeight`，
  校验两个因子都取得到且乘积 = 登记值；正文出现贡献值却没有派生行即失败。

## 演示样例口径（与项目名闸门的关系）
- **演示身份只认显式声明**：总控 `--demo` 或 `工作区参数.json` 的 `demo: true`。
  为 true 时全链传递：`评分表.json` / `权重表.json` / `依据对照表.json` 均写 `demo: true`，
  四件产物加「演示样例」页脚；校验规则一条不放宽。
- **项目名只做提示**：项目名含「演示 / 合成 / 非真实 / 示例」时，总控打一行提示并写入运行报告，
  不自动判定为演示、也不自动放行；名字换成真实片区名不会把演示数据洗白（评分表仍带 `demo` 标记，
  总控在 08 步会拦住「数据是演示、运行没声明」的情况）。
- 评分表里的依据格写**赋分口径**（如「按 0–10 分标度对方案在该指标上的表现赋分」），
  不写数据来源真伪声明；演示身份靠标记字段与页脚承载，不靠正文措辞。

## 基线文件（`记忆与规则/验证基线-CardoAHP.json`）
基线内容随项目而变，**不得写死**：由本次运行的独立复算结果生成，
字段为 `criteriaWeights` / `globalWeights` / `templateSha256`（可选 `schemeScores` / `schemeOrder`）。
模板 sha256 = `9E97F57F…B27C0`（标准模板 sha 锁定值，全项目一致）。
换评分测试：删 `schemeScores`/`schemeOrder` 或整份基线即可，不改脚本。

### 基线模式（`--baseline-mode`，与 CardoInvest / CardoOSGB 同一套口径）

| 模式 | 行为 |
|---|---|
| `auto`（默认） | 基线不存在→自举写入；存在→真对账 |
| `write` | 强制重写基线 |
| `check` | 只对账不写（基线不存在则跳过该项） |
| `none` | 完全跳过基线段 |

由 `工作区参数.json` 的 `baselineMode` 控制（默认 `auto`）。
实测：首跑自举写入 → 二跑 15 项全过真对账 → 篡改基线立即被抓（exit 1），对账不是走过场。

> 路径修正（2026-10-30）：原 `DEFAULT_WORKSPACE` 取 `parents[3]`，指向的是**技能包目录**
> （CardoAHP），而非工作区，导致基线永远探测不到。已改为 `parents[4]`（工作区根）。
