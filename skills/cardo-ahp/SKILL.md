# CardoAHP · AHP 量化流水线

一个文件夹就是这条流水线：把 `CardoAHP/` 整个放进用户的项目文件夹，**不用安装、不用配置**。

**独立工作区、独立交付**：一个包一个工作区、一份交付；四包放同一目录不会自动串联，也不共用状态文件。
跨包只靠产物交接——把上游产物复制进本包 `输入文件/`。
**本包只吃问卷**：不接收低空实测数据；实测进现状与投资，不进 AHP 权重层（理由见通用规范第一节第 3 条）。
判断 vs 实测的分工与单会话自足要求，见《Cardo 四包通用规范》（`交付规范/Cardo四包通用规范.md`）。

**放料清单**：`开工.py` 会在工作区生成 `放料清单.md`，列出要什么、放哪、现在到没到；本文档是执行细则。
**首次运行自动备依赖**：缺依赖就在用户缓存（`%LOCALAPPDATA%\cardo\venv-ahp`）按 `requirements.txt`
建虚拟环境并安装（阿里云→清华→USTC→官方源回退），之后复用；技能包目录保持只读。
需本机已装 Python 3.9+。


**技能包只读**：本文件夹里的 `SKILL.md`、`开工.py`、`requirements.txt`、`Skills/`、`assets/` 在开工过程中一个字节都不会被写；
运行期状态只写工作区与用户缓存。
工作区默认是**本文件夹的上一级目录**（独立使用时即项目文件夹，如 `XX项目/`；以插件方式安装时请用 `--workspace` 指定项目目录）：`输入文件/` 放料、`过程文件/` 留痕、`成果文件/` 出活，
`工作区参数.json` 和 `.cardo/`（虚拟环境）也在那里。换项目时把技能文件夹整体拷走即可，不会带走任何项目数据。

在项目文件夹里执行命令（`--workspace` 可显式指定别的工作区）：

```powershell
python CardoAHP\开工.py
```

## 开工四步

**默认场景是空白文件夹 = 全新项目**。用户手上什么都没有时，系统该做的是
**把要人填的空白表一次铺出来、把「要你定的事」列清楚**，等用户填完放回原位再算 ——
而不是先卡在「缺参数」上让人自己猜。

**第 0 步（每个工作区都会自动做）**：`开工.py` 在工作区根生成 **`放料清单.md`**（按项列出「要什么 / 放哪儿（绝对路径）/ 怎么命名 / 是否必需 / 现在到没到」）
和 **`怎么填.md`**（讲清三张人填的表：方案清单怎么定方案、专家问卷填哪几格、方案评分表填哪一列）。
两个文件每次运行都会刷新。想一项一项确认，跑：

```text
python CardoAHP\开工.py --intake
```

**空工作区首跑自动铺表**（`make_templates.py`）：
- `输入文件/03-方案打分表/方案清单.xlsx` —— **空白待填** + 「候选方案参考」页（常见方案类型清单，供挑选，不是让你照抄）
- `输入文件/02-专家问卷（待发放）/AHP专家问卷-专家N.xlsx` × N —— 空白问卷
- 方案评分表**不预生成**：评分表列数 = 方案数，要等方案清单填好才知道（预生成会与实际方案数对不上、已填得分作废）

**新项目要定的事，一律让用户在拿得到的模板里填，不要替他猜**：
- **项目名称**：填在《方案清单.xlsx》的 **B1 格** —— 用户打开表填一格就行，
  不必问 AI、不必改参数文件。系统**刻意不从文件夹名推断**（文件夹名常是「测试-AHP」这类内部代号，
  猜出来的名字会让成果印上一个没人认可的项目名）。`--project "正式全称"` 仍可覆盖。
  **没填 → 成果用占位名，第 09 步闸门会拦住不让交付**（闸门名：「项目名已填真实名称（否则成果上印的是占位名）」）。
- **候选方案**：默认**全空白**（用户自己定，行数不限）。想先看常见候选让他改 → 跑
  `--preset-schemes` 预填三套常见方案。**预填与否是策略选择，要问用户，不替用户定**。
- **专家人数**：默认 5 位（聚合下限；7 位更稳），标注建议理由，`--experts 6` 可改。

项目名的读取顺序（pipeline `load_cfg`）：《方案清单.xlsx》B1 格 > 工作区参数.json > 空。
`工作区参数.json` 带 `projectNameSource` / `expertsSource` 标 sheet|user|param|suggest|unset。

1. **定方案**：打开 `输入文件/03-方案打分表/方案清单.xlsx`，在「方案清单」页填方案名（可增删行，不比的标「否」）。
   「候选方案参考」页给的是常见思路（按改造强度/功能路径/实施节奏/资金模式分类），挑中的抄过来改名即可。

2. **领卷（发卷）**：

```powershell
python CardoAHP\开工.py --to 02
```

   产出 5 份 `AHP专家问卷-专家N.xlsx`，同时落在两处：
   - **领料区**（人可见，发给专家用）：`输入文件/02-专家问卷（待发放）/`
   - 过程留痕：`过程文件/02-问卷生成/问卷空白/`（含机读 `问卷清单.json`）

   **把领料区的空白问卷发给专家，不要另造表。** 问卷是匿名的（封面项目名固定占位），这一步**不需要项目全称**。

3. **回收**：专家填完的问卷**文件名不要改**，放进 `输入文件/02-专家问卷（已回收）/`，**至少 5 份**；
   顺手在 `专家名单.xlsx`（已自动释放）补角色与回收状态（可选）。回收后跑 01→07：

```powershell
python CardoAHP\开工.py --to 07
```

4. **算权重**：`--to 07` 产出 `成果文件/AHP权重表.xlsx`（第 09 步装配后归位到
   `成果文件/成品版/AHP权重表/AHP权重表_成品版.xlsx`），含准则权重、指标权重、综合权重与 CR 检验。

5. **方案打分**：`python CardoAHP\开工.py --from 07`（或直接 `python CardoAHP\开工.py`）跑到 08 ——
   08 会**按《方案清单》的实际方案数生成空白评分表并停下**（方案名已预填好）。
   你只需填黄色格 0–10 分与依据列（指标ID/权重/标准不要动）。填好后：

```powershell
python CardoAHP\开工.py --from 08
```

`开工.py` 每次运行都会：依赖自检（缺就建 `.cardo/venv-ahp`，按 阿里云 → 清华 → USTC → 官方源 回退安装）→ 建目录 → 释放四准则模板与专家名单
（模板 sha 锁定，第 07 步会校验原件未被改写）→ 校验参数与问卷份数 → 调流水线。`--check` 只校验不开工。

## 输入

| 项 | 必需 | 放哪 | 要求 |
|---|---|---|---|
| AHP 四准则模板 | **是** | `输入文件/01-AHP四准则模板/` | 首次运行自动释放，sha 锁定，勿改 |
| 空白问卷 | 否 | `输入文件/02-专家问卷（待发放）/` | 首跑自动生成，发给专家用 |
| 回收问卷 | **是**（≥ 03 步） | `输入文件/02-专家问卷（已回收）/` | `AHP专家问卷-专家N.xlsx`，至少 5 份，准则层 1–9 标度、指标层比值标度 0.1~10；**每份内容必须互不相同**（同 sha256 会被 03 步硬拦） |
| 专家名单 | 否 | `输入文件/02-专家问卷（已回收）/专家名单.xlsx` | 首次运行自动释放空白表 |
| 候选方案清单 | 否（首跑释放） | `输入文件/03-方案打分表/方案清单.xlsx` | 空白待填 + 候选方案参考页；方案名以此为准 |
| 方案评分表 | 否（08 生成） | `输入文件/03-方案打分表/AHP方案评分表.xlsx` | 08 按清单的方案数生成，方案名预填，填 0–10 分与依据 |

发卷阶段（`--to 02`）不要求问卷已回收，也**不要求项目全称**（问卷匿名）；`--to 02` 之后每一步都要求 ≥ 5 份。

## 方案与打分项：哪些能改、哪些不能

| | 谁定 | 能不能改 |
|---|---|---|
| 比哪几个方案 | **用户** | 自由。数量不限（一般 2~4 个），名字自定 |
| 每个方案打多少分 | **用户** | 0–10 分 + 依据 |
| 打分项（16 项指标） | 系统（按项目方向规则） | **不能随意改** |
| 综合权重 | 系统算 | 不能改 |

**为什么打分项不能留空**：专家问卷就是按这 16 项打的，权重从这 16 项算出来，
评分表再用这 16 项给每个方案打分。改了打分项，权重就对不上，专家问卷也得重发重打。
指标适用性（`required` / `optional` / `not_applicable`）由**项目方向**决定，不是由方案决定 ——
所有方案共用同一套指标，排名才有可比性。

## 参数（工作区参数.json）

| 键 | 取值 | 说明 |
|---|---|---|
| `projectName` | 全称 | 项目名称，可用 `--project` 覆盖 |
| `experts` | 5–7，默认 5 | 专家人数，可用 `--experts` 覆盖 |
| `baselineMode` | `auto`（默认）/ `write` / `check` / `none` | 验证基线模式：auto=首跑自举写入基线、之后每次真对账；write=强制重写；check=只对账；none=跳过 |

## 退出码

`开工.py` 对外只给三种结果：**0 跑完 / 3 需要人工介入 / 1、2 真失败**。
停在 02、03、06、08、09 步需要人接手的，一律返回 **3**（内层 `pipeline.py` 单独跑时步骤失败返回 1，是内部口径）。

| 码 | 停在哪 | 什么性质 | 读哪份报告 | 下一条命令 |
|---|---|---|---|---|
| 0 | 全过 | 成功 | — | 去 `成果文件/` 取货 |
| 3 | 02 步 | 等你发卷、收问卷 | 工作区根 `放料清单.md` | 收齐 ≥5 份原样放回回收区，再 `--to 07` |
| 3 | 03 步 | 问卷缺项 / 标度不合规 / CR 超限 / **同一份问卷被复制成多份** | `过程文件/03-回收校验/回收校验报告.md` | 退给对应专家本人改那几格，改完 `--from 03` |
| 3 | 06 步 | 群体矩阵 CR≥0.1 | `过程文件/06-一致性校准/校准记录.md` | 人工批准最小改动候选后 `--from 05` |
| 3 | 08 步 | **正常停顿**：首次生成空白评分表 | 工作区根 `放料清单.md` | 填 `输入文件/03-方案打分表/AHP方案评分表.xlsx` 后 `--from 08` |
| 3 | 09 步 | 独立复算有失败项（含基线对账超差） | `过程文件/09-成果验证与成稿/独立验证报告.md` | 逐项核对后 `--from 09` |
| 3 | 开工前 | 缺料、缺参数、等你确认 | 工作区根 `放料清单.md` | 按输出逐条补，再 `--to 07` |
| 1 | 某一步 | 真失败（脚本/结构错） | `过程文件/00-总控/运行报告.md` | 按定位改文件后 `--from <步>` |
| 2 | — | 环境或结构问题 | 终端输出 | Python 需 3.9+；模板被改动则删掉该模板文件后重跑；依赖装不上按提示换源 |

**查重（`AHP-E-DUP-EXPERTS`）**：回收区里若有 ≥2 份问卷的 sha256 完全相同，说明是同一份问卷被复制成多份，
会被当成多位独立专家参与聚合 —— 但实际只有 1 位专家的判断，属静默失效，第 03 步硬拦。
处理：把多余副本移出回收区（或换成该专家真正填写的那一份），确认 ≥5 份内容各不相同后 `--from 03`。
**只读不改**：查重只算文件哈希，不动用户的问卷文件。

## 成果与验收

- **成品版（对外交付，一成果一子目录）**
  - `成果文件/成品版/AHP权重表/AHP权重表_成品版.xlsx`
  - `成果文件/成品版/AHP方案评分结论/AHP方案评分结论_成品版.xlsx`
  - `成果文件/成品版/AHP权重与评分结论/AHP权重与评分结论_成品版.docx` 与同名 `.pdf`（封面独立成页、目录页码按 PDF 分页静态回填；**正式交付以 PDF 为准，docx 为可编辑稿**）
- **内部件（复核用）**
  - `成果文件/内部件/AHP权重表/AHP权重表_溯源版.xlsx`、`成果文件/内部件/AHP方案评分结论/AHP方案评分结论_溯源版.xlsx`（附「内部核对」页：源 JSON 与 sha256）
  - `成果文件/内部件/AHP权重与评分结论/AHP权重与评分结论_溯源版.docx`（多一章「溯源说明」）
  - `成果文件/内部件/AHP依据对照表/AHP依据对照表.xlsx`
  - `成果文件/内部件/依据数据/`：权重表.json、评分表.json、群体矩阵.json、矩阵集.json（随包带走，离开本机仍可逐数回指）
- 09 独立复算必须「失败 0 项」；成品版不得引用 `过程文件/`、`内部件/` 等内部路径，
  也不得出现「演示数据/合成演示/示例数据/非真实依据」等禁词与缺口、占位措辞。
  演示运行时，合成问卷口径只在成品版「一、方法与口径」写一句，其余正文按正式报告写；
  该句按段落位置白名单放行，别处出现同类词即判不通过（`交付装配.py` 闸门）。
- 输入文件/成果文件里只允许常规 Office 文件（JSON/MD 只能留在 `过程文件/`；
  `内部件/依据数据/` 是随包取证依据，按约定例外放行）。
- 向用户说明：AHP 结论只反映专家判断，不替代财务测算；专家人数与回收份数要写清。

## 缺料怎么办

- 问卷 / 评分表**必须真人填**：不能用网络检索或模型推测替代，缺份就停并登记缺口。
- 只有背景资料（政策依据、专家所属单位名称等）允许联网检索补，且必须标来源（机构 + URL + 日期），写进 `过程文件/00-总控/网络补料/`，不进 `输入文件/`。

## 纪律

1. 不替专家填问卷、不编造判断矩阵或得分；缺份就登记缺口。
2. 不改模板、不改标度口径、不移动原始资料；`Skills/` 与 `assets/` 只读。
3. 一次只问一个决策。
4. 失败翻译成「哪一步、缺什么、放到哪、下一条命令」，不贴大段堆栈。
